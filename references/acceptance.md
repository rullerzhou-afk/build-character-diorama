# 验收、比较与交付

事实、审美判断与未验证事项分开。截图只证明截图时的画面；动作需连续观看或完整过程证据。程序检查不代替视觉和设备验收。

按交付层级与改动范围选用以下项目。交互试作先验证约定的主要体验并说明限制；完整交付再覆盖约定设备、网络与发布条件，不把本次未要求的能力扩成任务。

## 实际操作

| 项目 | 观察内容 |
| --- | --- |
| 资源与首屏 | 本地 HTTP 打开，加载、缺图、失败恢复、首次出场顺序 |
| 空间 | 默认与极限镜头、竖屏及动作中的裁切、侧薄、露背、遮挡和漂移；画片转向与输入联动按 [production.md](production.md) 检查 |
| 互动 | 普通按钮或场景点击完成整段及第二遍，有可见结果 |
| 接触 | 接触前、交接、结果与恢复，检查完整扫过范围、部件切口及位置／大小／朝向跳变；按 [motion.md](motion.md) 区分表现路线 |
| 操作异常 | 连点、动作中重置、拖动松手、键盘、失焦恢复 |
| 场景聚焦与收拢（有此需求时） | 按 [scene-focus.md](scene-focus.md) 检查退场、支撑、附属物、镜头、反向还原与原有互动 |
| 减少动态 | 实际切换并验证功能，做不到则记录未测 |
| 页面 | 真实文案、长内容、字体、气泡避让、滚动与控件空间 |
| 日夜联动（有此需求时） | 按 [day-night.md](day-night.md) 验收首帧、各时段视觉、自动与手动切换、跨页与后台恢复；保留同条件画面及连续过程 |
| 性能与清理（相关改动时） | 按 [runtime-checks.md](runtime-checks.md) 比较实际运行成本；涉及退出或重建时检查资源与回调恢复到稳定基准 |
| 交付条件 | 按需检查网络、部署与回访缓存，本地成功不代替线上成功 |

取景或布局验收记录请求与实际视口、画布显示尺寸和截图像素尺寸；窄屏检查横向溢出。resize 后等布局稳定并完成新绘制再截图，异常先核对尺寸与绘制时序。未测真实手机写“浏览器竖屏”；结束后清除本轮测试覆盖，不改动无关用户设置。截图扩展名与实际格式一致。

验收名称必须与实际触发条件相符。后台恢复要确认页面确实进入 hidden 或目标生命周期，再观察恢复；打开另一标签页不一定隐藏被测页面。纯逻辑中的存储异常模拟不等于浏览器存储策略已验收；页内减少动态开关与操作系统偏好分别记录，未触发的路径仍为未验证。

证据范围要覆盖结论：只录场景画布不能证明整页首屏无闪白或界面与场景同步，这类结论需保留包含加载层和控件的连续过程。帧采样、亮度统计和自动检查可辅助定位，不能单独证明局部光照质量或整个过渡无异常。

需要定位切换跳变、但不能连续观看时，用真实输入启动同一路径，再由既有步进入口逐步绘制并记录帧序列；重点检查交接、换帧组或换表现方式前后的相邻帧。注明步长和覆盖区间，只对这些样本下结论；真实帧时长下的表现、节奏和自然度未观察时仍记未验证。

## 可复现的状态与取景

需要前后比较或重复定位问题时，选少量相关状态，沿用实例已有入口或明确的操作顺序复现。若需要补轻量步进入口，按 [runtime-checks.md](runtime-checks.md) 处理；只记录影响判断的条件：

| 条件 | 记录与核对 |
| --- | --- |
| 场景状态 | 请求与实际应用的模式、角色动作时间或进度、日夜输入、收拢进度；随机布局或粒子影响画面时固定种子 |
| 取景 | 实际视口、画布尺寸与 DPR、相机类型、位置与观察目标、缩放或视野参数；需要对齐时另记主体占比、位置和控件占用区域 |
| 证据归属 | 本轮代码与资产版本、截图或过程文件、浏览器与渲染后端；复用证据仍按下文标明版本 |

等资源就绪，应用并核对实际状态后冻结影响截图的运动，待布局稳定且完成新绘制再捕获。模拟需固定推进步数，仅固定每步时长仍可能截到不同状态。状态缺失、未应用或尚未就绪时不能用目标名称冒充成功；记录实际状态与限制。测试覆盖与访客偏好分开，结束后恢复约定状态。

同一场景精修优先保留原镜头。比较不同构建时，相同世界坐标不等于相同画面占比；选明确参照，如地台宽度与底边或角色的投影范围，保持几何比例和约定观察方向，将完整动作范围放进扣除控件后的可用区域。默认构图与比较用取景分别保存，注明调整；不靠拉伸画面或裁掉问题区域让差异消失。

固定状态只支持静帧比较，不能证明互动路径成功。连续动作仍用真实输入完整操作；性能测量应在运行状态进行，按 [runtime-checks.md](runtime-checks.md) 区分首次加载与预热后的测量。

## 单独判断审美

先在目标屏幕的默认镜头下观察选定的关键一刻：能否看清主要角色、动作和结果，动作是否表达出约定的意图。再看身份与代表色、材料与连接、前后层次、光线、场景与页面平衡及节奏。区分执行者判断与用户选择。

以同一镜头、尺寸、动作状态与光线比较前后，一次主要改一个问题层。概念差异不一定失败，要判断是否破坏已选方向。保存可信基准、候选、取舍与回退原因，技术正确但不好看也可回退。

每轮记录：具体问题 → 原因假设 → 修改 → 同条件复查。不要只写“已优化”或没有依据的质量百分比。

改动过的视觉路径重新采集证据。复用旧截图或录像时注明所属版本与覆盖范围，并确认相关路径未变；不能把修改前的证据当作最终版本的新验收。

## 评估本 skill 时

本节用于评估方法效果，普通作品制作跳过。

冻结使用的 skill 与哈希，记录输入资产、已知项目背景、工具、生成次数、修订轮次、人工选择和作者介入。复用上一轮资产须列出；同一执行者续作不能称为完全独立冷启动。

授权与工具允许时可作独立试作：提供明确简报与预算，不喂原作品和隐含答案；完成前不回填目标答案，之后按真实失败窄修并区分版本。

比较案例先列路线、素材投入、选择者和修订量。少素材原型与多轮精修成品的差异不能直接证明 skill 的上限；一次结果不能保证跨主题稳定性。

## 交付

按约定交付可运行文件或获授权链接、启动方法、简报、来源与完整提示词、动作范围、默认与竖屏截图、动作观察、版本与限制。各项标“已观察达标／仍需调整／未验证”并附证据。

区分生成资产、程序构建、占位和真实网页截图。概念图不作为运行截图，说明哪些质量依赖审美选择。第三方库保留许可，来源记录不等于版权认定。发布按用户范围处理。
