# 场景聚焦、收拢与还原

用于点选主体后让其他物件退场、收拢地台并调整镜头，或把整个场景收起再展开。按实际需求选用；简单角色回应不需要引入场景模式。具体主体、造型、时序、曲线与取景参数留在实例中。

## 1. 先定义可见结果

写清完整场景、聚焦场景和返回后的画面各保留什么，以及入口与出口。区分“缩入地面”“缩小成模型”“隐藏外围”和“折叠结构”：只有真实折叠结构才需要铰链或新姿态，不把普通缩放说成折叠。

- 确定保留的主体、交互目标、活动范围、地台与必要附属物。整个场景消失时，仍有可见、可操作的恢复入口。
- 选择退场顺序、镜头变化和页面内容变化。交互动作中收拢时，明确继续、等动作完成或取消并恢复；不能意外丢失道具或重复计数。
- 连续改选以明确策略处理：从当前可见状态转向新目标，或先退回再进入。多主体切换只在实际需要时实现。

## 2. 按归属组织对象

先记录可信的初始位置、旋转、缩放、可见性和阴影状态。缩放根节点放在合理的落脚点或收拢中心；已有对象重新归组时保持世界位置连续，不让它们先跳一下。

建筑与屋顶、家具与桌上物、花盆与植物分别明确归属。角色、持物、附着灯、光晕、局部阴影、粒子和点击区域也要归属正确；静态和动态对象不能因实现位置分散而被漏掉。运行中的动画继续更新自身局部姿态，由所属组负责场景变换，避免两段动画争写同一个属性。

灯芯缩小或隐藏时，照明范围和强度按设计一起收敛；隐藏网格不代表隐藏独立光源。绑定到场景外部的灯光目标、软阴影和飘动物件同样检查。隐藏或缩得很小的物件退出命中与焦点顺序，避免留下看不见的点击目标。

亮度归零不一定取消独立的投影贡献，缩放中的光源靠近接收面时尤其要检查舞台外阴影。按所用渲染器同步控制投影，并验证恢复；优先采用连续参数，避免在过渡中反复切换需要重新编译的渲染配置。日夜光照基准与场景可见系数分开组合，不在缓存后的亮度上逐帧累乘。

## 3. 编排退场、地台与镜头

用一份过渡状态驱动各组、地台、附属物、镜头和相关界面。通常让外围物件先退出、支撑地台后收拢；还原时先恢复支撑，再让物件出现。顺序服从空间关系，不机械复制同一延迟。

收拢后的地台覆盖主体的完整动作路径，而非只覆盖静止姿态。检查缩放中心、表面高度、接触阴影和地面材质是否仍合理；避免物件悬空、穿过保留的主体，或纹理被过度拉伸。

镜头以保留对象及动作范围取景，纳入页面控件占用的空间。区分对象缩小和镜头缩放，避免两者叠加导致主体忽大忽小。允许拖动时，在边界视角与窄屏下复查遮挡和裁切；返回采用约定的原视角或默认视角，不能意外丢失用户设置。

保存需要复查的镜头及画面占比，自动适配范围时保留约定的观察方向；按 [acceptance.md](acceptance.md) 选择取景参照，区分默认构图与比较时的对齐。

过渡可有挤压、回弹或错峰，但先用简单变换验证空间关系。角色、玻璃、画片与投影分别检查中间态，端点成立不足以证明全过程自然。

## 4. 可逆操作与其他状态

切换途中反向，从当前可见进度继续；不重复创建对象或叠加计时器。完成后恢复约定的准确基准，反复操作不累计偏移。返回按钮始终可达，键盘焦点不能留在已隐藏界面上。

场景模式与日夜、互动计数、角色动作各有明确关系；收拢不应顺便清空这些状态。减少动态可直接切换端点或采用短过渡，仍保留操作结果。后台恢复按当前目标求值，不补播积累的每一帧。

## 5. 实际验收

| 路径 | 观察与通过条件 |
| --- | --- |
| 收拢与还原 | 实际按钮或场景点击完成双向全过程及第二遍，主体、支撑、附属物、镜头和界面按约定联动 |
| 中间态 | 保存代表性过渡画面并连续观看，无悬空、穿帮、孤立亮斑、残留阴影或透明重影 |
| 中途反向 | 在不同阶段返回、再次进入，位置连续，最后选择生效，最终回到准确基准 |
| 更换主体 | 仅在实现多主体时验证；旧主体退出与新主体进入关系明确，镜头、状态和点击范围一致 |
| 原有互动 | 在完整与聚焦场景分别执行；动作中切换按约定处理，道具交接、路径、计数保持正确 |
| 日夜与光照 | 有日夜时检查各端点及过渡；退场灯不留下照明，保留主体与操作目标仍可辨 |
| 视口与输入 | 桌面、目标窄屏和边界镜头检查完整活动范围；鼠标、触屏等价操作、键盘与恢复入口可用 |
| 减少动态与恢复 | 实际触发对应路径后检查最终可见状态；未触发的后台或系统偏好不记为通过 |

证据记录实际视口、模式、操作顺序与版本；画布录像用于场景动作，涉及界面与焦点时另留整页过程证据。沿 [acceptance.md](acceptance.md) 区分逻辑检查、视觉判断和未验证项。
