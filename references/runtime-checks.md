# 性能与资源清理检查

用于首批较多素材接入、需复现动作中间态、增加运行负担，或涉及场景退出与重建。按本次交付层级和受影响部分选择检查；普通小修不必做完整性能审计。

## 先明确更新与归属

沿用场景已有更新循环，按实际功能明确状态、镜头、画片朝向、接触求解、屏幕标注与最终绘制的依赖顺序，不为每项功能另起一套循环。各层只写自己负责的状态或局部变换，再由已有状态计算最终画面，避免多个回调争写同一属性。

区分实例独占与共享资源。几何合批、实例化或缓存复用前，保留仍需独立运动、命中、变形或退场的对象及其归属；优化不能破坏交接与收拢。

需反复观察动作中间态时，随首个主要互动保留轻量调试入口：暂停、按固定步数推进、读取实际状态，并在推进后完成绘制。沿用现有循环，不另建测试框架。与动作绑定的气泡和特效使用同一可暂停进度，避免等待的墙上时间已过、动作却因低帧率尚未完成；日夜等真实时间输入独立处理。调试入口不进入普通访客流程，恢复与取证按 [acceptance.md](acceptance.md)。

## 素材进入场景时

生成图较多时，首批运行素材接入就记录传输体积，并按目标网络条件做一次加载观察，别等全场景完成后才发现成本。试作记录实际条件与限制，正式交付再验证约定的网络与设备范围。

保留源图，根据实际显示尺寸及允许的近景另导出运行版本；压缩文件体积与限制纹理尺寸分别处理。可比较 WebP 等支持所需透明度的格式，在真实画面核对细节、颜色和透明边，再决定采用哪一份。优化不能损坏握点附近的轮廓或暴露关节切口。

## 测量后再选优化

固定代表性的视口、画质和真实运行状态，记录设备、浏览器、渲染器版本与后端、DPR、窗口可见状态及测量方法。首次加载和可交互时间单独记录；连续运行的测量在资源与效果预热后进行，不能拿冻结截图的空闲成本作结果。

按问题选择指标，不要求全部采集：

| 现象或改动 | 有用的观测 |
| --- | --- |
| 首屏慢或首次操作停顿 | 资源体积与加载阶段、首次绘制和可交互时间、编译或上传停顿 |
| 增加几何、灯光或效果后卡顿 | 实际运行的帧时间及波动、绘制调用与三角形、DPR、阴影和透明叠层；有工具时分别定位 CPU 与 GPU 成本 |
| 反复进入退出后变慢 | 预热后同状态的资源数量、更新回调与事件是否累积 |

核对计数含义：纹理数量不是显存字节，不同渲染器的同名字段也未必可直接比较。软件渲染、后台节流与真实设备结果分别说明；只看到固定刷新率下的帧率上限不能证明还有余量。不设所有作品共用的调用次数或帧率门槛，按目标设备与改动前基准判断。

针对实际瓶颈调整 DPR、阴影、透明叠层、重复网格或贴图尺寸；每轮保留同条件的画面和成本对照。保护角色辨识点、接触与主要互动，减少动态偏好与低画质策略分别处理。

## 隐藏与销毁分开

收拢、临时隐藏或暂停通常仍需恢复，按恢复需要保留资源，不把隐藏自动当成销毁。真正退出或替换场景时，由资源所有者清理：

- 注销本场景的更新回调、监听器、计时器、动画任务与观察器；迟到的异步加载结果不能重新挂回已退出场景。
- 停止并解除本实例使用的动画或控制器。按所用库的接口释放独占几何、材质、贴图和渲染目标；移出场景树不等于释放 GPU 资源，释放材质也不等于释放贴图。
- 共享资源交给共同所有者，在不再被使用时释放；避免对共享材质和贴图做无差别递归清理，也避免重复释放同一资源。

涉及此路径时实际重复退出与进入，确认互动、绘制和资源回到预热后的稳定基准，没有重复响应或持续增长。保留的共享缓存可说明用途，不要求计数归零。按 [acceptance.md](acceptance.md) 记录实际观测范围，未测长期运行就不作长期稳定结论。
