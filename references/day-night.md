# 日夜联动：制作与验收

用于需要随时间或用户选择改变场景的任务。实现、生成新素材和发布沿用本次授权。日夜是按需能力，不默认给每个场景加入时间系统、多页面或新服务。

阅读顺序：约定行为 → 定义共享状态 → 制作各时段外观 → 接入首帧与切换 → 实际验收。照明问题配合 [production.md](production.md)，页面与加载顺序配合 [presentation.md](presentation.md)。

## 1. 约定时间与操作

在实例简报中写清下表。沿用已有约定；缺少约定时，可采用设备本地时间、自动跟随、手动日/夜覆盖并可返回自动，记录这是执行者选择。

| 决策 | 需要确定的内容 |
| --- | --- |
| 时间来源 | 设备本地时间、项目指定时区或已有服务时间；跨地区展示以谁的时间为准 |
| 时段 | 日与夜是否已足够，是否需要晨昏；各时段边界与过渡区间由画风和产品需求决定 |
| 自动行为 | 开页、持续打开、跨边界、后台返回时何时重新计算 |
| 手动覆盖 | 支持哪些模式、是否持续覆盖自动、如何返回自动；按钮显示用户选择与当前有效时段 |
| 保存范围 | 仅本页、同一会话或下次访问；多页面及多标签是否需同步 |
| 联动范围 | 哪些环境、角色、灯、界面随时段变化；哪些保持原样；是否包含已授权的行为变化 |

日夜时段与系统深浅色偏好分别定义，只有产品约定时才建立映射。定时美术切换可以采用固定时刻，并如实说明；真实日出日落需要地点、日期和可信计算来源，明确要求时再引入，不为普通氛围效果额外请求定位或服务。

## 2. 定义单一状态来源

采用能满足现有工程的最小实现：一个共享计算函数或已有状态层通常足够，不另建通用时间框架。

- 分开保存用户模式（如 auto/day/night）、时钟输入和计算后的有效时段/过渡进度。多页面共享的是模式与时间规则，不能把某次算出的“夜晚”当成永久偏好。
- 先解析有效手动覆盖，再在自动模式下按当前时间计算。返回自动立即重新读时间，不恢复过期的旧时段。
- 环境、角色、灯、页面和加载层消费同一份有效状态；每个房间可有不同灯光参数，但时段定义一致。
- 用户模式、有效时段及其界面标签随状态更新；视觉参数没有变化时也要核对这些语义状态。颜色相同或已到端点不能成为跳过边界标签更新的理由。
- 保存偏好时使用项目自己的键和受控枚举值。无效值或存储不可用时使用约定默认值，并保证当前页仍能切换；重置主题只处理相关偏好。
- 同页由共享状态通知；独立页面在首次显示、返回和刷新时重读；需要多标签同步时才接入对应机制。不要假设持久化写入会自动通知当前页面。
- 保留可替换的时钟输入供测试。测试时间、强制模式与访客偏好分开，调试结束恢复真实来源，避免测试设置悄悄留存。

把午夜当成连续的时间环处理，明确跨零点的区间。自动模式从当前时间推导目标状态，避免靠定时器累计“走过多少秒”而随后台暂停漂移。

## 3. 先制作外观，再接自动时钟

固定镜头、尺寸和角色动作，制作白天与夜晚两个端点；有晨昏需求再加中间基准。先通过手动预览确认美术成立，然后接时间驱动。可使用参数表，也可使用少量素材变体，选择服从既有表现方式。

| 层 | 制作要点 | 观察标准 |
| --- | --- | --- |
| 背景与远景 | 协调天空/底色、窗外、雾与远景对比；按需求出现星月等元素 | 窗内外处于同一时段，远景不过亮抢主体 |
| 环境与主光 | 调整主光方向、色温、强度和环境补光；晨昏有明确过渡 | 白天有方向，夜晚有明暗层次，主体轮廓可读 |
| 局部灯光 | 联动灯芯外观、附近受光面和必要的柔光范围 | 灯旁的墙、桌面或地面有可见响应；遮挡与范围符合画风 |
| 角色与植物画片 | 为受光、无光照或混合材质分别设计亮度与色彩响应 | 身份色可辨，与周围融为一体，透明边不发白、脸不发黑 |
| 表面与玻璃 | 协调反射、高光、透射、烘焙光和接触阴影 | 夜间不会残留突兀的白日高光，接触与透明排序成立 |
| 页面与加载层 | 联动页面底色、卡片、文本、按钮、焦点与遮罩 | 字可读，控件状态可辨，加载与场景风格一致 |

发光材质与附近照明分别检查：灯芯自身亮不能证明它照亮了物体。按表现方式选择真实光源或经过设计的局部照明效果；发光和晕光不能穿过不应穿透的家具或遮住角色。

插画中已有的明暗不会自动随三维光源改变。先尝试材质响应与受控混合；若烘焙光根本冲突，再按授权加工或制作同身份素材变体。变体保持画布、锚点、尺寸、透明轮廓和动作接口，切换时角色不漂移、不换脸。记录新增资产与限制。

过渡分别调节相关参数，共用同一进度。端点好看不代表直接插值也好看：在相同镜头与角色状态下对照过渡中段的色彩、明暗和主体可读性。若直接混合出现不合适的灰浊，可加入经美术确认的中间配色与照明基准；暖色暮光只是可选方向，不能成为所有作品的固定模板。多基准混合使用一致、归一化的权重，让各层处于同一过渡阶段。

颜色插值遵守渲染器既有颜色空间约定，避免重复变换。切换贴图或灯开关时处理突跳、双重阴影和透明重叠；日夜资源应在应用新外观前就绪，加载失败保留完整可用状态并提供恢复方式。局部灯的开关对照与舞台外投影检查见 [production.md](production.md)。

先修代表性局部：角色、附近物件与页面文字；有局部灯时包含灯和受光面。端点与适用的中间态都可用后再扩展到其余场景。具体时刻、亮度、配色和素材属于实例，不写成所有作品的统一参数。

## 4. 接入首帧、切换与恢复

**首次显示。** 在可见页面样式和场景首次绘制前读取模式、解析当前时间并生成同一份状态。需要异步数据时使用一致的等待状态；资源就绪后整体呈现。首屏、加载层和场景依次出现时不应先闪出另一时段。招呼等动作仍等遮罩退出后开始。

**持续运行。** 按场景需要更新目标时段，视觉插值使用渲染循环。跨边界应连续且不反复抖动；短时间连续切换从当前实际显示的混合状态过渡到最新目标，取消过期过渡，不叠加计时器。正向、反向及中途改选都要检查，不能从上一次目标或固定端点重新起步。

**手动操作。** 选择白天或夜晚后保持覆盖，自动时钟更新不能抢回控制；返回自动重新计算此刻状态。时间切换不重建角色、重置互动计数或打断正在交接的道具，除非简报明确要求相应行为。

**后台返回。** 页面重新可见、导航返回或设备时钟/时区发生变化后，在下一次更新按约定的时间来源与时区重新求值；项目固定时区不随设备时区改变。避免补播后台积累的每一步过渡。明确采用直接校正或一次短过渡，手动模式仍遵守覆盖规则。

**减少动态。** 保留日夜与模式切换能力，取消或缩短长渐变及附带氛围运动；结果仍清晰可见。操作可通过键盘与触屏完成，状态变化有可读标签，键盘焦点不因重绘丢失。

资源与更新规模按实际页面控制：复用材质、光源和已加载资源，避免每帧重新创建。没有需求时不新增背景轮询、角色作息、声音或天气系统。

## 5. 实际验收

在实际可运行页面上执行。逻辑测试可验证时间规则，浏览器操作验证接入，截图与连续观察验证视觉；三者的结论分别记录。按本次交付层级、约定目标和实际能力选取下表用例，未测的适用项记录未验证；多页面、多标签、资源变体等只测实际实现的能力。

| 用例 | 操作与通过条件 |
| --- | --- |
| 白天、夜晚端点 | 在相同镜头、尺寸与角色状态下截图对照；逐层核对第 3 节，角色、交互目标与文字可辨；有局部灯时做开关对照，检查灯旁受光面及舞台外投影 |
| 晨昏与中间态 | 有渐变就观察正反方向全过程及中间画面，无突然发灰、过曝、全黑、透明重影或灯闪；未设计的晨昏时段记不适用，仍检查已有的手动切换渐变 |
| 自动边界与午夜 | 注入每条边界之前、当时、之后的时间及跨午夜输入；有效时段符合约定。让测试时钟实际推进跨边界，确认场景与标签均更新，包括视觉参数已不再变化的边界 |
| 首次加载 | 用日、夜时间分别全新打开或刷新；再用已有手动偏好打开，观察首帧和加载全过程，确认无错时段闪屏且出场时机正确 |
| 手动覆盖与返回自动 | 点选白天/夜晚后让时钟跨边界，覆盖仍生效；返回自动立即依据此刻时间；标签、场景与存储行为相符 |
| 连续切换 | 在过渡中途快速往返改选，确认从可见状态连续转向，最后选择生效，无过期过渡回跳、重复计时器或操作失效 |
| 导航与保存 | 按约定测试进入其他页面、返回、刷新或重新访问；首次可见状态一致。跨标签同步仅在已实现时验证 |
| 后台与时区变化 | 在自动模式隐藏页面，确认实际进入 hidden 或目标生命周期后，推进时钟并恢复；测试所支持的时区/时间变化，再检查手动模式不被覆盖。使用时钟注入，通常无需改设备设置；没有实际隐藏则该路径未验证 |
| 互动与减少动态 | 日、夜均完成主要互动；动作中切换，角色、道具、计数保持连续；实际启用减少动态后仍可操作 |
| 不同尺寸与视角 | 在目标桌面、窄屏与低高度视口，以及允许的镜头边界查看明暗、遮挡、画片白边；各主题下用真实文案核对新控件、卡片、气泡与焦点，不能只查横向溢出 |
| 失败与回退 | 测试无效/不可用偏好存储；有异步时间或素材变体时再测试对应失败。结果符合回退约定，场景和控件仍可用 |

判断未通过时写明具体层和现象，例如“夜晚角色画片仍保持白天亮度”或“返回室内先闪白再读偏好”。沿同一镜头和条件修复、复查，避免用总曝光掩盖局部问题。

## 6. 记录结果与交付

- 保存实例的时间来源、时区、边界、覆盖优先级、持久化范围、联动清单和回退策略。
- 保存同条件的日/夜截图；有渐变时加中间态。用连续过程证据记录首屏、跨边界与切换；结论涉及页面、加载层或控件时必须覆盖整页，不能仅凭场景画布录像或静态截图判断无闪屏。
- 每条适用用例标记“已观察达标／仍需调整／未验证”，不适用项说明原因。记录浏览器、实际视口、测试时间/模式、实际触发条件和构建版本；模拟时钟、逻辑异常模拟、浏览器竖屏、真实设备及系统偏好分别注明。证据尺度与复用边界见 [acceptance.md](acceptance.md)。
- 测试结束恢复交付约定的默认模式与真实时间，清除本轮测试覆盖。保留实际用户偏好，说明仍未验证的设备或路径。
